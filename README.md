# Контрольная точка 6: деревья и кучи

Практикум по алгоритмам. Шесть задач, решения на Java.

| № | Задача | Класс | Подход | Время | Память |
|---|---|---|---|---|---|
| 1 | Суммы по уровням дерева | `LevelSums` | обход в ширину по уровням | O(n) | O(n) |
| 2 | k самых частых чисел | `TopFrequent` | подсчёт + куча размера k | O(n + d log k) | O(d) |
| 3 | Медиана потока | `RunningMedian` | две кучи | O(n log n) | O(n) |
| 4 | Маршрут максимальной стоимости | `MaxPathSum` | спуски снизу вверх | O(n) | O(n) |
| 5 | k-я сумма пары | `KthPairSum` | куча, слияние строк | O(k log min(n, k)) | O(min(n, k)) |
| 6 | Медиана скользящего окна | `WindowMedian` | две половины в TreeSet | O(n log k) | O(k) |

d в задаче 2 это число различных значений.

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test                          # тесты
gradlew run -q --args="2" < input.txt # задача 2, ввод из файла
```

Номер задачи передаётся аргументом, входные данные читаются из stdin в формате
из задания, ответ печатается в stdout. Например, для задачи 6:

```
4 2
1 4 2 3
```

ответ `2.5 3.0 2.5`.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.

## 1. Суммы по уровням дерева

Обход в ширину от корня 0. Очередь лежит в массиве, и вершины одного уровня
идут в ней подряд: перед началом уровня запоминается конец очереди, и всё до
него относится к текущему уровню. Сумма копится в `long`, потому что на одном
уровне может быть больше 100 тысяч значений по 10^9.

Рекурсии нет. Дерево из 200 000 вершин может быть цепочкой такой же глубины,
и рекурсивный обход на нём упал бы с `StackOverflowError`.

## 2. k самых частых чисел

Частоты считаются в `HashMap`. Дальше нужны k лучших, где «лучше» значит
большая частота, а при равной частоте меньшее число. Числа проходят через кучу
размера k, на вершине которой худший из отобранных. Когда в куче становится
k + 1 элемент, худший выбрасывается. В конце куча разбирается от худшего
к лучшему, и ответ заполняется с конца.

Полная сортировка всех различных чисел дала бы O(d log d). Куча размера k
быстрее при маленьком k и не хуже при k = d.

## 3. Медиана потока

Две кучи: `lower` с меньшей половиной чисел (наверху максимум) и `upper`
с большей (наверху минимум). В `lower` столько же чисел, сколько в `upper`, или
на одно больше. Тогда медиана видна сразу: при нечётном количестве это вершина
`lower`, при чётном среднее двух вершин.

Новое число кладётся в `lower`, максимум `lower` переезжает в `upper`, и если
`upper` стала больше, её минимум возвращается обратно. После этого все числа
`lower` не больше чисел `upper`, а размеры снова в норме. Каждое число стоит
три операции с кучей, O(log n).

Среднее двух центральных считается через `long`, чтобы сумма двух чисел
около 10^9 не переполнила `int`. Медиана целых чисел всегда целая или с половиной,
поэтому вывод собирается из удвоенного значения: `-1.5`, `2.0`, `-0.5`.
`String.format` не подходит, в русской локали он печатает запятую.

## 4. Маршрут максимальной стоимости

У любого маршрута есть самая верхняя вершина. Маршрут через неё это сама
вершина плюс, может быть, лучший спуск в левое поддерево и лучший спуск в правое.
Спуск `gain[v]` это лучшая стоимость пути из `v` только вниз:
`value[v] + max(0, gain[левого], gain[правого])`. Отрицательный спуск выгоднее
не брать, поэтому он заменяется нулём.

Для каждой вершины ответ-кандидат `value[v] + max(0, gain[левого]) + max(0, gain[правого])`,
итог это максимум кандидатов. Если все значения отрицательные, ответом будет
наибольшее из них: маршрут из одной вершины.

Потомков нужно посчитать раньше родителя. Вместо рекурсии вершины обходятся
в порядке, обратном обходу в ширину: в нём любой потомок стоит дальше родителя.

## 5. k-я наименьшая сумма пары

Суммы с фиксированным `i` образуют отсортированную строку
`A[i] + B[0] <= A[i] + B[1] <= ...`. Задача сводится к слиянию n отсортированных
строк. В куче лежит по одному кандидату из строки, наверху наименьшая сумма.
Вынули пару `(i, j)`, на её место кладём `(i, j + 1)`. Пара, вынутая k-й, и есть ответ.

Строки с номером `i >= k` можно не заводить: перед любой их суммой стоят
по крайней мере k сумм `A[0..k-1] + B[0]`. Поэтому в куче не больше `min(n, k)`
пар, и работа не зависит от `m`.

Одинаковые суммы от разных пар учитываются отдельно, как требует условие:
каждая пара вынимается из кучи сама по себе.

## 6. Медиана скользящего окна

Как в задаче 3, окно делится на меньшую и большую половины. Но теперь из окна
уходит элемент, и удалять его нужно из середины половины, а куча быстро удаляет
только вершину. Поэтому половины хранятся в `TreeSet`, где удаление любого
элемента O(log k).

В множествах лежат индексы, а не значения, и сравниваются по паре
(значение, индекс). Так одинаковые значения не склеиваются в один элемент, и
удаляется ровно тот, что ушёл из окна.

Шаг окна: новый индекс кладётся в нужную половину, ушедший удаляется, затем
размеры выравниваются перекладыванием крайнего элемента из одной половины
в другую.

## Решения по неоднозначным местам условия

- Задача 2: k чисел печатаются в одной строке через пробел.
- Задачи 3 и 6: значения печатаются с точкой в качестве разделителя (`1.5`),
  независимо от локали системы. Отрицательная половина печатается как `-0.5`.

## Тесты

- на каждую задачу граничные случаи и сверка с переборным решением на случайных
  входах (для деревьев случайные деревья с перемешанной нумерацией вершин);
- входы максимального размера из ограничений с таймаутом 5 секунд, в том числе
  дерево-цепочка из 200 000 вершин и суммы, которые не помещаются в `int`;
- `MainTest` проверяет чтение ввода и формат вывода для всех шести задач.
